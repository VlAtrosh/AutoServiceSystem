# RISK_REGISTER.md

## Реестр рисков проекта AutoServiceSystem

| ID | Риск | Признак/доказательство | Вероятность | Влияние | Меры снижения |
|----|------|------------------------|-------------|---------|---------------|
| R-01 | Потеря данных при перезапуске контейнеров | Использование `docker compose down -v` удаляет volume с БД | Высокая | Высокое | Использовать резервное копирование БД, исключить `-v` в production-скриптах, настроить автоматический бэкап |
| R-02 | Неавторизованный доступ к API | Отсутствует проверка прав доступа на некоторых эндпоинтах | Средняя | Высокое | Добавить проверку ролей (get_current_admin) для всех чувствительных эндпоинтов |
| R-03 | Ошибки валидации NULL значений в БД | Поля vin, color могут быть NULL, что вызывает ошибку 500 | Средняя | Среднее | Исправить схемы Pydantic (Optional[str]), добавить обработку NULL в репозиториях |
| R-04 | Медленная загрузка страницы при большом количестве данных | Отсутствует пагинация на некоторых списках, загрузка всех записей сразу | Средняя | Среднее | Реализовать пагинацию, добавить индексы в БД, оптимизировать запросы |
| R-05 | Отсутствие HTTPS при реальном развёртывании | Токены передаются в открытом виде через HTTP | Высокая | Высокое | Настроить SSL-сертификат, использовать HTTPS в production |
| R-06 | Конфликт версий Docker при развёртывании на другой машине | Использование специфичных версий образов | Низкая | Среднее | Закрепить версии образов в docker-compose (postgres:16, nginx:alpine) |
| R-07 | Ошибки при создании заказа из-за неправильной связи client_id | Связь между users, clients и orders неочевидна | Средняя | Высокое | Документировать связи, добавить проверки в бэкенде |
| R-08 | Отсутствие мониторинга логов в production | Нет централизованного сбора логов | Средняя | Среднее | Настроить сбор логов (ELK, Loki), добавить оповещения об ошибках |
| R-09 | Некорректное отображение статусов заказа | В модели OrderStatus разные значения (accepted, diagnostics, waiting_approval...) | Низкая | Низкое | Привести статусы к единому стандарту, добавить маппинг во фронтенде |
| R-10 | Проблемы с CORS при развёртывании на другом домене | Настройки CORS ограничены localhost | Низкая | Высокое | Настроить переменные окружения BACKEND_CORS_ORIGINS для production |

## Оценка рисков

### Критичные риски (требуют немедленного внимания):
- **R-01** Потеря данных (вероятность высокая, влияние высокое)
- **R-02** Неавторизованный доступ (вероятность средняя, влияние высокое)
- **R-05** Отсутствие HTTPS (вероятность высокая, влияние высокое)

### Риски среднего приоритета:
- **R-03** NULL значения в БД
- **R-04** Производительность
- **R-07** Связь client_id
- **R-08** Мониторинг логов

### Риски низкого приоритета:
- **R-06** Конфликт версий Docker
- **R-09** Статусы заказа
- **R-10** CORS

## Вывод по рискам

Проект имеет несколько критических рисков, связанных с безопасностью и сохранностью данных, которые необходимо устранить перед реальной эксплуатацией. Рекомендуется:

1. Настроить регулярное резервное копирование БД
2. Внедрить HTTPS
3. Провести аудит прав доступа к API
4. Документировать связи между таблицами для новых разработчиков
